# Описание архитектуры взаимодействия систем «Умный дом» в PropDevelopment

## 1. Внутренний контур PropDevelopment

**Внутренняя зона (Internal Zone)** компании PropDevelopment включает следующие компоненты:

### Мобильное приложение собственников
**Mobile App (tenant-core)** — это точка входа для пользователей (собственников недвижимости). Через это приложение жильцы взаимодействуют с системой: отправляют команды на открытие домофона или шлагбаума, управляют настройками устройств «Умного дома».

### Сервис интеграции «Умный дом»
**Smart Home Integration Service** — это центральный компонент интеграции, который:
- Принимает запросы от мобильного приложения
- Сохраняет и читает настройки устройств из базы данных **tenant-core-db**
- Проходит аутентификацию через **auth-service-1 (Keycloak)** для валидации токенов доступа
- Транслирует внутренние запросы в формат, понятный внешней платформе партнёра

### Сервис аутентификации
**auth-service-1 на базе Keycloak** обеспечивает:
- Выдачу и валидацию OAuth2-токенов
- Проверку прав доступа пользователей
- Единую точку аутентификации для всех сервисов PropDevelopment

---

## 2. Демилитаризованная зона (DMZ)

Между внутренней инфраструктурой PropDevelopment и внешней платформой партнёра расположена **DMZ-зона**, которая включает:

### API Gateway
Шлюз выполняет критически важные функции безопасности:
- **Rate Limiting** — ограничение частоты запросов для защиты от DDoS-атак и злоупотреблений
- **WAF (Web Application Firewall)** — фильтрация вредоносного трафика, защита от OWASP Top-10 уязвимостей
- **Logging** — централизованное логирование всех запросов для аудита и расследования инцидентов

### Межсетевой экран (Firewall)
Все соединения между внутренней зоной и DMZ защищены:
- **mTLS (mutual TLS)** — взаимная аутентификация сторон по сертификатам
- Строгими правилами фильтрации трафика

---

## 3. Внешняя платформа партнёра

**External Smart Home Partner Platform** — это облачная платформа внешнего партнёра, которая предоставляет сервисы «Умного дома». Она включает:

### Сервис интеллектуального домофона
**Intercom Service** отвечает за:
- Распознавание лиц (Face Recognition)
- Управление доступом через видеодомофон
- Обработку команд на открытие двери

### Сервис интеллектуального шлагбаума
**Barrier Gate Service** обеспечивает:
- Распознавание автомобильных номеров (Plate Recognition)
- Управление доступом на парковку/территорию ЖК
- Обработку команд на открытие шлагбаума

### IoT-устройства
Физические устройства, установленные в жилых комплексах:
- **Intercom Devices** — видеодомофоны с камерами и биометрическими сканерами
- **Barrier Devices** — контроллеры шлагбаумов с камерами распознавания номеров

---

## 4. Поток данных и взаимодействия

### Сценарий 1: Открытие домофона через мобильное приложение

1. **Собственник** нажимает кнопку «Открыть дверь» в мобильном приложении
2. **Mobile App** отправляет запрос в **Smart Home Integration Service** с OAuth2-токеном
3. **Smart Home Integration Service** валидирует токен через **Keycloak**
4. Сервис проверяет права доступа пользователя и сохраняет логи в **tenant-core-db**
5. Запрос проходит через **Firewall** с mTLS-аутентификацией
6. **API Gateway** проверяет запрос на наличие атак, применяет rate limiting
7. Запрос по защищённому каналу **HTTPS/OAuth2** отправляется на **External Smart Home Partner Platform**
8. **Intercom Service** отправляет команду на **Intercom Device** по IoT-протоколу
9. Домофон открывает дверь

### Сценарий 2: Автоматическое открытие по биометрии

1. **Собственник** подходит к домофону
2. **Intercom Device** сканирует лицо и отправляет данные на **Intercom Service**
3. Сервис распознаёт лицо и проверяет список разрешённых пользователей
4. Если доступ разрешён — отправляет команду на открытие
5. Событие логируется и отправляется обратно в PropDevelopment для сохранения в журнал доступа

### Сценарий 3: Настройка доступа через мобильное приложение

1. **Собственник** добавляет члена семьи в мобильном приложении
2. **Mobile App** отправляет данные в **Smart Home Integration Service**
3. Сервис сохраняет настройки в **tenant-core-db**
4. **Smart Home Integration Service** через API Gateway отправляет данные о новом пользователе на **Partner Platform**
5. Платформа партнёра регистрирует биометрические данные (лицо) или номер автомобиля
6. Подтверждение возвращается обратно в PropDevelopment

## 5. Протоколы и технологии

| Компонент → Компонент | Протокол | Безопасность |
|----------------------|----------|--------------|
| Mobile App → Smart Home Integration Service | REST/HTTPS | OAuth2 Bearer Token |
| Smart Home Integration Service → Keycloak | OAuth2/OIDC | mTLS |
| Smart Home Integration Service → tenant-core-db | JDBC | Внутренняя сеть |
| Internal Zone → API Gateway | HTTPS | mTLS + Firewall |
| API Gateway → Partner Platform | HTTPS | OAuth2 Client Credentials |
| Partner Platform → IoT Devices | IoT protocols (MQTT/CoAP) | TLS 1.3 + Device Certificates |

---

## 6. Ключевые принципы архитектуры

1. **Защита периметра** — все внешние вызовы проходят через DMZ с API Gateway
2. **Минимизация доверия** — mTLS между всеми компонентами, даже внутри периметра
3. **Единая аутентификация** — Keycloak как центральный провайдер идентичности
4. **Сегментация** — чёткое разделение на Internal Zone, DMZ и External Platform
5. **Полный аудит** — логирование всех операций доступа к устройствам
6. **Отказоустойчивость** — резервные каналы связи и graceful degradation при недоступности партнёра

Такая архитектура обеспечивает баланс между удобством для собственников, безопасностью данных (особенно биометрических) и надёжностью работы критических систем доступа.
